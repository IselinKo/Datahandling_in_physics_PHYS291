Data in files
Storing data is quite a science. There are numerical data, history records, video records,
simply lots of different data to store for future use.
For example at MIT https://libraries.mit.edu/data-management/store/formats/
where we can read:
     
as an example of considerations. For physical sciences the situation is even more
complicated. The numerical data really allow to establish easily ad hoc rules
which easily can later be misinterpreted. That calls for standards, which in turn
might lead to conversion problems and so on. We can not study all this in detail
in this course.

In high energy physics lots of data are stored in root files. These are very well
documented and can store "nearly anything", as we have seen using the "TBrowser".
For those who are not going to work in CERN or particle physics it can still be
useful to learn this as an example, or perhaps even carry this with you to other
fields of science.

There are other similar standards like HDF (Hierarchical Data Format, also HDF4
and HDF5), netCDF (Network Common Data Format), data stored in databases, XML etc.
If you will work e.g. in climate science or some geographical science, you will be
able to find tools for that - and the work here will help you to understand
such tools. As below, just the awarness of these matters will help you in future.

We shall learn to work with data in plain text format (txt which is ASCII) and also
with the (binary) root files (perhaps also XML, CSV, GPSX etc)

We have already started to work with another CERN invention, the HTML format, which
you are in contact many times every day (hidden behind).
The HyperText Markup Language (HTML) is more relevant for presentation than storing
of data, but general experience with this is very useful. HTML is closely related to
the XML (eXtensible Markup Language) which is so to say everywhere (GPSX, configuration
files of many devices, Office documents, etc).

As another example (related!) we shall shortly look into another type of binary
files, which we know as DOCX, PPTX - or in the above recommended open replacement
- ODF, Open Document Format - files ODT and ODP.
( Some ten-fifteen years ago the former were in a type of turbulence about openness
but since then Microsoft has won again without solving the problems). One could spend
weeks to read about all of this; instead we can remark that there were and there
still are problems - simply awarness of these problems can already be an advantage.
Many people, even scientists, are happily ignorant about all that.
(We could also see that Apple can be discussed too, yes open standards ....)

Remember from the top: the ODF (ODF) is to be preferred (open standard, specified, public),
the Microsoft formats (OOXML) should be avoided (proprietary, the standard is often broken,
unreliable over time) - and often too complex with sort of ad hoc extensions.

Main part of exercise 6

The package of data for this week builds on the materials from many previous years.
There are some data files, as e.g. data in text form basic.dat.txt and some
summary and comments files, as described in the text below.

In Part I of this exercise, the following concepts will be explored:
1. Reading and writing of arrays of data from and to text files. Text files
are human-readable, but inefficient for machine - digits must be converted
and each number might have different number of digits.
Files from root (*.root) or for example matlab files (*.mat) are storing numbers
in binary format, not as digits. We will not attempt to go into details of this now.


2. Reading and writing of arrays using ntuples (class TNtuple) into
the special root files. Not human readable, but efficient storage and
access by root commands/scripts.
What is ntuple, n-tuple, tuple - read https://en.wikipedia.org/wiki/Tuple

3. Several aspects of how to treat data arranged in ntuple-objects
- contained in the special root files - filename.root


In PART II we shall explore how to connect ntuples and graphs.
Suppose we have an ntuple with "columns" x,y,z,w, such that these columns
represent data for three functions: y(x), z(x), w(x).
First we shall make this ntuple as in part I.
Then we learn the implemented functionality to plot these functions one by one.

This is implemented by a construction ( provided TNtuple* ntup )
    ntup->Draw("y:x","","l");
unlike the histogram-drawing of one of the "columns" or "branches"
    ntup->Draw("y");
in Part I.

We can plot such single graphs by such a single function,
but combining several plots into one graph and enhancements are difficult.
Therefore we learn to work with "Getting Primitive Graph" - as is indicated.

A special topic is "cloning" of objects, in our case whole graphs.
This is to prevent - for example - that changes made after
a graph window would modify the objects displayed in that window.
