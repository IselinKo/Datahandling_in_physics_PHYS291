Compilers    (Compare to Interpreters )


In contrast to interpreters, the compilers require
a program file (or source file) with extra definitions
and perhaps comments - documentation.

You call the compiler with the input file and possibly some
extra options, like the name of the resulting compiled program,
which is also sometimes called the executable.

On unix/linux usually
gcc progfile.c produces a.out which you run by ./a.out
if you write
gcc -o prog progfile.c that produces prog which you run by ./prog
(gcc can be replaced by e.g. gfortran etc, but then with progname.f)

We have got the example files comp.c and comp.f, also comp.cpp
They are in the directory compiles (and compiles2 - identical files)
In our case these files also contain instructions for compilation and execution
comp.c
  

comp.cpp
  

comp.f
  


  



  

To appreciate the difference between work with interpreter and compiler:
try to modify the "programs" to run for 1 to 20 (do the following)

in the interpreted case you just replace the 5 or 6 by 20 and enter it
in root (or python, or perl etc)

In the compiled case you must
first edit the comp.c by e.g.      nano comp.c
then compile it by      gcc -o C_comp comp.c
then run ./C_comp

Using sftp for Secure File Transfer

To transfer files between computers, sftp is a common method.
The name is a short for Secure File Transfer Protocol, and allows a user to
log in to a remote machine, browse the files there, and upload or download files.

Today there are several graphical interfaces to sftp, and you can often use your
browser as a sftp client. However, we will here concentrate on the original,
text based sftp.

What we will do here is just to demonstrate the sftp in the listing is
